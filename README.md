## The Hard Parts (Core Challenges & Architectural Solutions)

## 1. What Happens When Constraints Cannot All Be Satisfied?

Paper generation is a constrained selection problem. Teacher requirements such as total marks, difficulty distribution, topic weightage, and question-type distribution may conflict because the question bank is finite and questions have discrete mark values.

For example, a request for **33% Easy questions in a 40-mark paper** corresponds to 13.2 marks. Since questions have discrete mark values, an exact match may not be possible. Similarly, a particular chapter may not contain enough questions of the requested difficulty or question type.

The system handles these cases explicitly rather than crashing or silently ignoring the teacher's requirements.

### Feasibility Before Generation

Before searching for a paper, the generator performs feasibility checks using:

- **Capacity checks** — verifies whether enough marks/questions are available for the requested constraints.
- **0/1 subset-sum reachability** — checks whether the required total marks can be formed from the available question marks.
- **Topic, difficulty, and question-type availability** — identifies cases where the question bank cannot provide enough suitable questions.

If the requested combination is feasible, the deterministic search attempts to satisfy the configured targets. If some soft targets cannot be matched exactly, the system retains the valid paper and reports the resulting deviations.

### Three Generation Outcomes

| Status | Meaning |
|---|---|
| `EXACT` | A valid paper is generated with the exact total marks and all configured soft-distribution deviations within the defined tolerances. |
| `PARTIAL` | A valid paper is generated and the hard requirements are satisfied, but one or more soft distributions cannot be matched closely enough because of the available question-bank composition or discrete mark values. |
| `IMPOSSIBLE` | The requested configuration cannot produce a valid paper under the hard constraints, such as an empty candidate pool, insufficient available capacity, or an unreachable total-mark combination. |

### Example

Suppose a teacher requests a specific percentage of Hard questions from a chapter, but the question bank does not contain enough suitable Hard questions.

Instead of:

- crashing,
- hanging during generation, or
- silently changing the requested configuration,

the system generates the closest valid paper when possible and reports the deviation as `PARTIAL`. If a valid paper cannot be formed while preserving the hard constraints, it returns `IMPOSSIBLE` with a diagnostic explanation.

This makes constraint trade-offs **visible and explainable to the teacher** rather than hiding them inside the generation process.

## 2. How Do You Make the Output Feel Like a Real Paper?

The generator considers both **question selection and exam structure**, rather than simply selecting random questions.

- **Structured Sections:** Questions are organized into MCQ, Short Answer, and Long Answer sections with appropriate mark values.
- **Balanced Selection:** The constraint engine considers topic, difficulty, question type, and marks together to avoid arbitrary question selection and improve syllabus coverage.
- **Deterministic Ordering:** Stable selection and tie-breaking make results reproducible and keep the paper consistently structured.
- **Continuous Numbering:** Questions are numbered sequentially across sections with marks clearly displayed.
- **Exam-Style PDF:** The `pdf-lib` exporter produces a clean A4, multi-page student-facing paper with exam details, instructions, and page numbering.

## 3. Can a Teacher Swap One Question Without Regenerating the Whole Paper?

Yes. The generator supports **individual question replacement** without rebuilding the entire paper.

- **Deterministic Swap:** Searches the question bank for a replacement matching the original question's subject, topic, difficulty, type, and marks.
- **Position Preservation:** Only the selected question changes; the remaining questions and their order stay unchanged.
- **Duplicate Prevention:** Questions already present in the paper are excluded from candidates.
- **AI Similar Question:** If no suitable bank question is available, the teacher can explicitly request an AI-generated similar question.
- **AI Enhancement:** Teachers can also preview AI-based wording improvements before applying them, with validation checks for mathematical and scientific content.

## Architectural Rationale & Self-Reflection

## Approach & Defense: Why Deterministic Logic + AI?

The project uses a **hybrid architecture**: deterministic logic handles paper generation, while AI is an optional assistant for language-related tasks.

- **Deterministic Core:** Paper generation uses feasibility checks, Dynamic Programming Beam Search, and local optimization to satisfy exact mark requirements and optimize topic, difficulty, and question-type targets.
- **Why Not Pure AI?** LLMs are useful for generating and refining language, but they are not reliable enough to enforce exact numerical constraints, prevent duplicates, or guarantee a valid paper structure.
- **AI as an Assistant:** Groq is used only for teacher-initiated question enhancement and similar-question generation. AI outputs are validated before they can be applied, while the core generator remains functional without the API.
- **Independent Validation:** The final paper is validated separately from the generation process so that totals, duplicates, question structure, and configured distributions are checked from the selected questions themselves.

This separation keeps **constraint satisfaction deterministic** while using AI where language generation provides value.


## Where It Falls Short & What I'd Do With More Time

The current system focuses on the core paper-generation workflow. With more time, I would add:

- **Internal Choices:** Support paired alternatives such as "Answer either A or B."
- **Case-Based Questions:** Model multi-part case-study questions with structured sub-questions and mark allocation.
- **Larger Question Bank:** Expand topic, difficulty, and question-type coverage to improve exact constraint matching.
- **Multi-Board Support:** Extend the configuration and section rules to other curricula such as ICSE and state boards.

## Strengths & Weaknesses

### One Thing I'm Proud Of

The strongest part of the project is the separation between **deterministic constraint solving** and **AI-assisted authoring**. The core generator uses a **Mark-Bucketed Dynamic Programming Beam Search** followed by deterministic local optimization and independent validation. This allows the system to enforce hard requirements such as exact total marks, valid question structure, and uniqueness while explicitly reporting when softer distribution targets cannot be fully satisfied.

AI is kept as an optional layer for question enhancement and similar-question generation rather than being responsible for the core constraint-solving logic.

### One Thing That's Still Weak

The main limitation is the **finite composition of the question bank**. Some combinations of total marks, topic weightage, difficulty, question type, and available mark denominations cannot be matched exactly because the required questions may not exist in sufficient quantity.

The system handles this by returning a `PARTIAL` result and showing the resulting deviations instead of silently violating the requested constraints. With more time, expanding the question bank with greater topic, difficulty, and mark-value diversity would improve the number of configurations that can be matched exactly.

## Quick Start / Local Installation

### Prerequisites

- **Node.js**: v18.18.0 or later (v20+ / v22+ recommended)
- **npm**: v9+ or later

### 1. Clone & Install Dependencies

```bash
git clone https://github.com/Ayushs135/Smart-Question-Paper-Generator.git
cd Smart-Question-Paper-Generator
npm install
```

### 2. Configure Environment

Copy the `.env.example` file to create your local `.env`:

```bash
cp .env.example .env
```

```env
DATABASE_URL="file:./dev.db"

# Optional: Groq API Key for AI Question Enhancement
GROQ_API_KEY=""
GROQ_MODEL="openai/gpt-oss-120b"
```

### 3. Initialize & Seed Database

```bash
# Push schema to SQLite database (creates dev.db)
npm run prisma:push

# Seed question bank (433 CBSE Class 10 questions)
npm run db:seed
```

### 4. Run Development Server

```bash
npm run dev
```

Open [http://localhost:3000](http://localhost:3000) in your browser.
