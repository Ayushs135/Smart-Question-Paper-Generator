# Smart Question Paper Generator

An intelligent academic assessment platform engineered for educators to generate balanced, syllabus-aligned **CBSE Class 10 Mathematics** and **Science** question papers.

## The Hard Parts (Core Challenges & Architectural Solutions)

### 1. What happens when constraints cannot all be satisfied at once?
In real-world paper authoring, requested percentages rarely map to neat integer multiples of question marks (e.g., asking for 33% Easy on a 40M paper equals 13.2 marks, but discrete questions are 1M, 2M, 3M, 4M, 5M, 6M, 8M). Furthermore, the question bank may have capacity limits in specific chapter/difficulty combinations.

The system handles these gracefully without crashing, hanging, or silently corrupting requirements:
- **Pre-Search Feasibility Analyzer (`lib/generator/feasibility.ts`)**: Before running candidate generation, a 0/1 Knapsack subset-sum DP algorithm evaluates whether the target total marks are mathematically reachable. It performs capacity checks across topics, difficulty tiers, and question types.
- **Graceful Multi-State Classification**:
  - `EXACT`: Achieved when total marks match strictly ($0\text{ M}$ error) and all soft distributions (difficulty, type, topic) fall within strict discrete tolerance thresholds (Total Variation Distance $\le 3\text{M}$ for difficulty/type, $\le 5\text{M}$ for topics across 14 chapters).
  - `PARTIAL`: When total marks are met but discrete question sizes require minor distribution trade-offs, the engine solves for the Pareto-optimal trade-off and presents an explicit breakdown drawer quantifying deviations (e.g., *Difficulty: ±1.0M, Question Taxonomy: ±2.0M*).
  - `IMPOSSIBLE`: When hard mathematical barriers occur (empty pool, insufficient total capacity, unreachable subset sum), the generator returns immediately with diagnostic violation details and the `closestAchievableMarks`, rather than throwing uncaught exceptions or returning an invalid paper.

### 2. How do you make the output feel like a real paper, not a random selection?
A real CBSE examination paper follows strict pedagogical structure, layout conventions, and cognitive progression:
- **Strict 3-Section Taxonomy**: Questions are partitioned into Section A (Multiple Choice Questions), Section B (Short Answer Questions), and Section C (Long Answer Questions), respecting actual question marks.
- **Continuous Question Numbering**: Sequential $Q_1 \dots Q_n$ numbering across all sections with right-aligned mark allocations (e.g., `[1]`, `[3]`, `[5]`).
- **Mark-Denomination Mixing**: Objective penalty terms discourage denomination monopolies (e.g., Section A mixes 1M and 2M MCQs; Section B mixes 2M, 3M, and 4M questions; Section C mixes 5M, 6M, and 8M questions).
- **Balanced Interleaving**: The generator cycles through chapters and cognitive tiers during beam expansion to ensure diverse syllabus coverage rather than clumping questions from a single chapter.
- **Vector A4 PDF Export (`lib/pdf/generatePaperPdf.ts`)**: Built with `pdf-lib` to render authentic CBSE examination documents with official headers, time duration, maximum marks, general instructions, and multi-page running footers.

### 3. Can a teacher regenerate or swap one question without redoing the whole paper?
Yes. The platform provides granular, non-destructive editing controls:
- **Deterministic 1-for-1 Swap Engine (`lib/generator/swapQuestion.ts`)**: A single teacher click replaces any question in-place. The engine queries the question bank for candidates matching the exact `subject`, `board`, `grade`, `topic`, `difficulty`, `type`, and `marks`.
- **Order & Position Preservation**: Unaffected questions maintain their exact positions, IDs, and marks. Candidate selection excludes questions already present in the active paper.
- **AI Similar Question Authoring**: If database alternatives for a specific combination are exhausted, teachers can click "Generate Similar" to author a fresh question matching the exact syllabus metadata via Groq LLM.
- **Phrasing Enhancement Preview**: Teachers can polish question phrasing with AI while strict Mathematics/Science safety gates prevent alteration of equations, numbers, formulas, or units.

## Architectural Rationale & Self-Reflection

### Approach & Defense: Why Hybrid Deterministic Logic + Guardrailed AI?
We chose a **Hybrid Architecture** with a deterministic core:
- **Pure AI Fails for Paper Generation**: Large Language Models are non-deterministic, suffer from arithmetic hallucinations, frequently miss exact mark totals (e.g., generating 38M instead of 40M), repeat questions, and cannot guarantee strict percentage adherence across 14 chapters.
- **Pure Logic is Authoritative**: Mark-Bucketed Dynamic Programming Beam Search combined with 0/1 Subset-Sum Knapsack guarantees 100% mathematical constraint compliance, zero duplicate questions, deterministic reproducibility, and sub-second execution.
- **AI as an Optional Assistant**: Groq LLM (`openai/gpt-oss-120b`) is restricted to teacher-initiated phrasing refinement and candidate drafting. Outputs pass through AST/regex safety validators before preview, leaving the core generation engine fully functional even if offline or without an API key.

### Where It Falls Short & What We'd Do With More Time
- **Internal Choice Generation**: CBSE board papers often provide internal options (e.g., "Answer either Q15A or Q15B"). Adding paired-choice constraint logic would further mirror board papers.
- **Case-Study Multi-Part Questions**: Class 10 exams feature 4-mark case-based questions with sub-parts (1M + 1M + 2M). Modeling hierarchical parent-child question structures would enrich Section C.
- **Multi-Board Expansion**: Extending schema support to ICSE and State Boards with custom section taxonomy rules.

## Strengths & Weaknesses

### One Thing I'm Proud Of

The strongest part of the project is the separation between **deterministic constraint solving** and **AI-assisted authoring**. The core generator uses a **Mark-Bucketed Dynamic Programming Beam Search** followed by deterministic local optimization and independent validation. This allows the system to enforce hard requirements such as exact total marks, valid question structure, and uniqueness while explicitly reporting when softer distribution targets cannot be fully satisfied.

AI is kept as an optional layer for question enhancement and similar-question generation rather than being responsible for the core constraint-solving logic.

### One Thing That's Still Weak

The main limitation is the **finite composition of the question bank**. Some combinations of total marks, topic weightage, difficulty, question type, and available mark denominations cannot be matched exactly because the required questions may not exist in sufficient quantity.

The system handles this by returning a `PARTIAL` result and showing the resulting deviations instead of silently violating the requested constraints. With more time, expanding the question bank with greater topic, difficulty, and mark-value diversity would improve the number of configurations that can be matched exactly.

## Quick Start / Local Installation

### Prerequisites

- **Node.js**: v18.18.0 or later (v20+ / v22+ recommended)
- **npm**: v9+ or later

### 1. Clone & Install Dependencies

```bash
git clone https://github.com/Ayushs135/Smart-Question-Paper-Generator.git
cd Smart-Question-Paper-Generator
npm install
```

### 2. Configure Environment

Copy the `.env.example` file to create your local `.env`:

```bash
cp .env.example .env
```

```env
DATABASE_URL="file:./dev.db"

# Optional: Groq API Key for AI Question Enhancement
GROQ_API_KEY=""
GROQ_MODEL="openai/gpt-oss-120b"
```

### 3. Initialize & Seed Database

```bash
# Push schema to SQLite database (creates dev.db)
npm run prisma:push

# Seed question bank (433 CBSE Class 10 questions)
npm run db:seed
```

### 4. Run Development Server

```bash
npm run dev
```

Open [http://localhost:3000](http://localhost:3000) in your browser.
